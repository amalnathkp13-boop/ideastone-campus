# Student portal workflow audit — 20 October 2026

Scope: student sign-in and the 12 available student modules, starting from main
`ae22f6b`. All writes used a separate `ci` database with synthetic college records.

## Reproduced defects and repairs

1. **Calendar extremes crashed the student portal.** Timetable requests for
   `9999-12-30` through `9999-12-31`, or `0001-01-01` through `0001-01-02` in
   Asia/Kolkata, returned HTTP 500 when calculating UTC boundaries. The service
   now returns a validation error; both HTTP requests return 400 with a recovery
   link and private/no-store headers. Model and authenticated HTTP regressions
   cover both boundaries.
2. **Rejected forms discarded student work.** Submitting an invalid profile phone
   discarded the entered city and phone, closed the edit form, and returned to the
   overview. The shared enhancement now restores editable fields and selected
   files to the matching form after validation failure, reopens its details
   container, and retains the current subpage. Hidden server values are refreshed
   from the response. Browser regressions cover profile validation and rejected
   request uploads.
3. **Saves hid the relevant subpage.** A profile or coursework save returned to
   the section overview. Same-section form responses now retain the subpage hash,
   keeping the saved personal details or submitted coursework visible. Both
   existing CI browser suites have explicit assertions.

## Local verification

- All 12 student module pages rendered in the browser: dashboard, profile,
  academics, timetable, attendance, exams/results, fees/payments, notices,
  requests/certificates, library, help/feedback and account/preferences.
- All 12 routes returned HTTP 200 and no-store headers. Unauthenticated module
  requests redirected to login.
- Browser: sign-in, rejected profile save with retained city/phone and open form,
  successful save, and coursework submission retaining the assignments subpage.
- HTTP/API: other-student placement denial, owner access denial, official identity
  write denial, own admission documents, published materials, receipt PDF output,
  foreign document/receipt denial, duplicate request retry, staff information
  request, student reply, approval, official certificate download, cancellation,
  notice acknowledgement, preferences, feedback, missing-CSRF denial and logout.
- Odoo module regression run: 79 tests, zero failures/errors. The subsequently
  added authenticated HTTP calendar regression passed in a focused run of seven
  HTTP tests. The new model boundary regression passed in the full module run.
- Ruff across addons/scripts, all addon XML parsing, changed JavaScript syntax
  checks and `git diff --check` passed.

## Limits

These checks establish the tested scenarios, not absence of every possible bug.
The new browser regressions run in the existing GitHub CI student/coursework
suites; their remote result must be checked on the PR. Local browser verification
used the desktop viewport; the existing CI suite covers 1440, 768 and 390 pixels.
SSO account provisioning, external LMS and production deployment were not
validated by this repair. Retaining unsaved form fields relies on the existing
JavaScript enhancement; manually reloading a rejected response discards the draft.
